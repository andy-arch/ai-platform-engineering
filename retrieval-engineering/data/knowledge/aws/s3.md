# Amazon S3

Amazon Simple Storage Service (S3) is an object store: data is stored as
opaque objects (a key, a blob of bytes, and metadata) inside a bucket,
not as files in a filesystem hierarchy or rows in a database. There is no
practical limit on total storage, and individual objects can be up to 5TB.

## Consistency

S3 provides strong read-after-write consistency for all operations: as
soon as a PUT succeeds, every subsequent GET or LIST (from any client)
reflects that write. This was not always true -- older S3 documentation
describes an eventually-consistent model -- but AWS made strong
consistency the default behavior across the service.

## Access control

Access to a bucket or object can be granted through IAM policies attached
to a principal, bucket policies attached to the bucket itself, or (less
commonly today) object ACLs. When both an IAM policy and a bucket policy
apply, the effective permission is the union of what either allows,
unless either contains an explicit Deny, which always wins. S3 Block
Public Access is a bucket- or account-level setting that overrides
individual policies to prevent accidental public exposure.

## Storage classes

S3 offers multiple storage classes trading cost against retrieval latency
and durability guarantees -- S3 Standard for frequently accessed data,
Infrequent Access tiers for cheaper storage with a retrieval cost, and
Glacier tiers for archival data retrieved on the order of minutes to
hours. Lifecycle rules can automatically transition objects between
classes, or expire them, based on age.
